[Open the gallery](index.html). All **112 scenes and 267 views**, including six
animations, were freshly captured with the current renderer. The 17 new action
scenes show actual swings/mining, bow draw/release in both directions, eating,
buckets, tilling/planting, a torch-lit cave and F5/F6/F7 travel at all three colour
zooms. Three new motion sequences show those actions continuously. The middle
colour zoom now retains the pixel art rather than switching to legacy glyphs.

See the [interaction review](../interaction-review-2026-10-16/README.md) for the
simulation fixes, ore census and actual native/co-op PTY checks. Source, capture
binary, input and output hashes are recorded in [evidence.json](evidence.json).

The original gallery checkpoint is preserved in Git at `40f3e11`. This refresh
captures current gameplay/art: Swamp hummocks/trees/reeds, bounded ore deposits,
the adopted frontal dragon and refined blocks. Biome portraits now choose the
actual surface; the hills portrait previously selected a cave floor near sea
level. The live camera keeps its jump dead zone and above-player framing.

All game data is opened in disposable temporary worlds; no player saves or model
services are used. [Every block/state before and after](../world-refinement-2026-10-15/index.html)
is available as a separate labelled audit, with ore census and verification.

The [catalog](catalog.json) gives each scene's origin, fixture source, image views

## Scene origin labels

Generated terrain is kept intact. Player/camera positions, time, and crystal entity
anchors are staged for inspection. The nine portal/glowstone checkpoints instead
execute and assert real placement, activation and travel commands in staged rooms;
Nether return requires the original linked frame after saving and reopening,
with no duplicate portal and with all three diamonds still in the chest. `Generated + light` adds a supported inspection
torch to otherwise native cave/dungeon geometry. Water-biome cards may stage a
boat. Creature lineups, co-op avatars, weather fixtures, UI, mining pose and the older portal
layout studies are explicitly labelled. Chat is an **unsent draft**; it contains no
fabricated model response. Trial poses use scripted commands/game updates and
staged positions, rather than a human playthrough. The recipe tower comes from the
existing declarative example, with seed 42; it is not freshly generated by an LLM.

Native captures use seed data `[1337,7331,9917,4444]`; creature lineups use
`[42,73,99,44]`. The existing trial, weather and staged cave fixture examples define
their own scene setup. Their exact source files and capture inputs are hashed.

The new **Co-op** category shows both players before travel, one travelling while
the other stays behind, their shared Nether arrival and independent return. These
replicas run through the actual native snapshot/terrain handlers. Tools, positions
and the source frame are staged; walking, ignition and portal use are ordinary
commands. Socket/reconnect behavior is tested separately. They are not recordings
of two humans or a WAN.

## Resolved gallery findings

The previous marker seed used a multiplier, offset and modulus divisible by three,
so every generated route landmark was a Shrine. The marker now uses mixed u32
arithmetic. A native-generation regression locates all three structures in both
positive and negative world directions. Bridge and reliquary cards now show
**actual generated structures**, replacing the simplified hand-built studies;
the original card identifiers are retained for existing links.

Enabling the variants also exposed side-view layout problems. Bridge pylons now
have walking cutaways, shrines have usable doors, and reliquaries have supported
floor-level loot and lights attached to the roof. Foundations provide a continuous
walking surface; shrine lava remains below the masonry platform. Short recessed
masonry back walls keep arch/pylon caps visually connected to their foundations
without adding collision to the cutaway. Geometry and
loot-support checks cover all three builders.

The return portal is functional, including clicking its bedrock frame and returning
to the Overworld; existing gameplay regressions cover that behavior. Calling it a
scaffold in earlier gallery notes was inaccurate. Small outer End islands remain
limited to the outskirts of the arena. End cities are not implemented; no gallery
card claims otherwise.

The frontal dragon is the playable default, with frontal melee/arrow/contact
regions and regression coverage. This gallery stages the encounter; it is not a
complete human boss-fight playthrough. The lava-layer cutaway puts the camera/player inside the
underground lava layer and does not show a safe spawn or open lava coastline.

## Reproduction

Requires Rust, Python with Pillow, and the DejaVu Sans Mono font used by the raster
helper. Use a fresh output directory and unset `NO_COLOR` for each capture.

```sh
cargo build --release --locked --example world_review --example village_review --example entity_review --example weather_review --example lantern_review --example pixel_review --example nether_review --example portal_review --example cooperative_review
export atlas_raw=/tmp/termcraft-world-atlas
mkdir -p "$atlas_raw"
env -u NO_COLOR target/release/examples/world_review "$atlas_raw/worlds"
env -u NO_COLOR target/release/examples/village_review "$atlas_raw/villages"
env -u NO_COLOR target/release/examples/entity_review "$atlas_raw/entities"
env -u NO_COLOR target/release/examples/weather_review "$atlas_raw/weather"
env -u NO_COLOR target/release/examples/lantern_review "$atlas_raw/trial"
env -u NO_COLOR target/release/examples/pixel_review "$atlas_raw/pixel"
env -u NO_COLOR target/release/examples/nether_review "$atlas_raw/nether" --creatures --animate
env -u NO_COLOR target/release/examples/portal_review "$atlas_raw/portals"
env -u NO_COLOR target/release/examples/cooperative_review "$atlas_raw/cooperative"
python3 scripts/build_world_gallery.py "$atlas_raw" /tmp/termcraft-world-gallery
# For the checked-in world and block galleries together:
python3 scripts/serve_gallery.py --port 8774
# Fetch and decode every gallery image/animation through that HTTP server:
python3 scripts/verify_gallery.py --base-url http://127.0.0.1:8774/ --report /tmp/gallery-images.json
```

The gallery embeds its catalog and static covers, with no external JavaScript/fonts or backend;
the HTML can also be opened locally. The builder emits contact sheets next to the
raw capture directory for visual review. Incremental animation frames are decoded
in order. The Nether clip has 72 samples at 60 Hz with a 20/10/20 ms GIF timing
pattern. Rain/snow clips have 48 samples at 20 Hz. These do not establish achieved
FPS, input latency, network behavior or human gameplay acceptance.

[Build/source/capture evidence](evidence.json) and [raw ANSI input hashes](capture-inputs.json)
identify the reviewed artifacts. This gallery alone does not qualify a beta release.

## Image delivery verification

Every world view, GIF frame and all 291 block-comparison images are decoded by
`scripts/verify_gallery.py`. HTTP mode requests every linked resource, requires
HTTP 200, compares returned bytes with the local artifact and checks each content
revision and expected image size. The world HTML's embedded catalog must match
the JSON catalog, and every scene must have a static cover. Covers load without
JavaScript; filters and the modal are progressive enhancements. Content-stamped
image URLs and the local server's cache headers refresh existing tabs after an
update. [HTTP verification record](image-loads.json).
